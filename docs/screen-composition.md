# Screen composition

Which `@giddy/components` library components build each screen in `docs/mocks/`, and which UI is built locally. It is binding (see `AGENTS.md`, "Components library is mandatory"): implement each screen from exactly the components it lists, and build locally only what it marks as local.

- **Sources:** the mocks (`docs/mocks/manifest.json` and every state file), the design system (`docs/design-system/`) and the library's public API (`frontend/projects/components/src/public-api.ts`). Components are named by selector.
- **Local UI** is layout and composition that belongs to one screen: grids, section spacing, page-specific arrangement and glue. It never restyles a library component.
- Mock-only chrome (`.mock-bar`, `.mock-note`) is excluded.
- The **marketing site** is itemized in full. The app's screens are itemized at summary level: the library components found in their mocks (all states), detected from the components' host classes; their local UI is the page layout in their feature library.

## Shell

| Part | Library components | Local UI |
|---|---|---|
| App shell (signed in) | `a[giddy-skip-link]`, `header[giddy-top-bar]` (brand: `svg[giddy-wordmark]`), `nav[giddy-sidebar-nav]` (brand: `svg[giddy-wordmark]`), `nav[giddy-bottom-nav]`, `giddy-toast-region`, `section[giddy-consent-bar]` | Shell grid in `frontend/src/app` |
| App public pages | `a[giddy-skip-link]`, `header[giddy-top-bar]`, `footer[giddy-footer]` | — |
| Marketing site (`frontend/projects/marketing`) | `a[giddy-skip-link]`; the page owns its header and footer (below) | `App` shell: `main#main` around the router outlet, `body[data-page]` stamping |
