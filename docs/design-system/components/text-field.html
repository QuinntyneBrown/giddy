Text field

Text fields collect short answers: the birthday child’s name, a parent’s email, the party date.

WCAG 2.2 AAStatus: stable

Overview

Every text field sits in a form field with a visible label. Use the right type and autocomplete so phones show the right keyboard and browsers can fill it: email, tel, date, number, postal-code.

Anatomy

  1. LabelVisible, above the field.
  2. Input40px, 1px --color-border-strong, --radius-md.
  3. HelpOptional hint, linked by aria-describedby.

Sizes

Large for the help search; small inside filter bars.

Responsive behaviour

  • Full width of their column; two fields sit side by side only from 768px and only when related (first/last name, date/time).
  • Font size stays 16px so iOS doesn’t zoom on focus.

Theming

Field tokens: --field-bg, --field-border, --field-radius. Dark surface night-900 with a lavender-grey border (5.45:1).

Accessibility

Role and pattern

Native <input> with <label for>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.

Focus

The ring sits on the border (offset 0) and the border turns focus colour.

Labelling

Visible label always; placeholder is a hint only. Errors link with aria-describedby and set aria-invalid. Use autocomplete for name, email, tel, postal-code.

Motion

Colour and border changes use --duration-fast (120 ms) with --ease-standard; reduced motion zeroes the duration in the tokens, so nothing extra is needed.

Touch

40px tall, full-width on phones.

Content

  • Labels are nouns: “Parent’s email”, “Party date”.
  • Help says why: “We’ll look within 10 km”.
  • Errors say how to fix: “Enter an email like name@example.com”.
