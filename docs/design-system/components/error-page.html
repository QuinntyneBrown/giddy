Error page

When something breaks, Giddy says what happened in plain words, keeps the chrome, and offers one way forward.

WCAG 2.2 AAStatus: stable

Overview

In-page errors use .empty.empty--error.card with a worried Giddy, Try again, a way back and a reference code. Whole-page errors (404, 403, 500, offline) use .status-page.

Anatomy

  1. Worried GiddyOrange balloon.
  2. TitleWhat failed.
  3. ReassuranceWhat’s safe.
  4. ActionsRetry + way back.
  5. ReferenceFor support.

Variants

404 “This page floated away” (sleepy) · 403 “This party plan is private” · 500 “Giddy tripped over a balloon string” · Offline “No internet right now”

Sizes

Not applicable: Block fills its card; status pages fill the viewport (70dvh).

States

VariantDefault
ErrorStatic; buttons carry states.

Didn’t load

Didn’t load

Responsive behaviour

  • Centred at all sizes.

Theming

Uses danger-tinted icon background and the worried mascot.

Accessibility

Role and pattern

In-page block is role="alert"; status pages have a single <h1>.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.

Focus

Retry is the first stop.

Labelling

Reference code in <code>.

Contrast

Text

Motion

None.

Touch

Buttons ≥ 40px.

Content

  • Say what happened, what’s safe, what to do. Never “Something went wrong” alone.
