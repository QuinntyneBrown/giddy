Menu

A menu groups a few actions behind one button, like the “⋯” on each checklist task.

WCAG 2.2 AAStatus: stable

Overview

Use a menu for 3–7 secondary actions on an item (edit, move, delete). Use visible buttons when there are only one or two. Menus are not navigation: page links live in the sidebar.

Anatomy

  1. TriggerIcon or text button with aria-haspopup and aria-expanded.
  2. Menu surfaceRaised surface, --shadow-3, --radius-md.
  3. ItemIcon + label, 32px tall.
  4. Danger itemDestructive actions last, after a divider.

Variants

Checkable items and a disabled item; shortcuts use <kbd> right-aligned.

Sizes

Not applicable: Menus have one size; width follows the longest item, minimum 12rem.

Responsive behaviour

  • On phones the menu opens as a bottom sheet when it has more than 5 items.
  • The menu stays inside the viewport; it flips above the trigger near the bottom edge.

Theming

Uses --color-bg-surface-raised and --shadow-3; dark mode raises to night-850 with a deeper shadow.

Accessibility

Role and pattern

WAI-ARIA APG Menu Button: role="menu", menuitem, aria-haspopup, aria-expanded.

Keyboard

KeyAction
Enter / Space / ↓Opens the menu and focuses the first item.
↑ ↓Moves between items.
Home / EndFirst / last item.
EscCloses and returns focus to the trigger.
LettersType-ahead to an item.

Focus

Focus moves into the menu on open and back to the trigger on close. Items show the shared ring inset plus the subtle background.

Labelling

The trigger names the object: “More actions for Order the dino cake”.

Contrast

Item text on raised surface
Danger item

Motion

Scales in from the trigger over --duration-fast.

Touch

Items are 32px tall with full-width hit areas; on phones the sheet uses 44px rows.

Content

  • Verb-first items: “Edit task”, “Let Giddy do it”.
  • Destructive item last, in danger colour, and it opens a confirmation.
