Dialog

Dialogs focus attention on one task, like booking a venue or deleting a party, and become bottom sheets on phones.

WCAG 2.2 AAStatus: stable

Overview

Use for short tasks that need the current page as context: add a guest, book Dino Den, confirm a delete. Long flows get their own page. The page behind becomes inert, the backdrop dims it and page scroll locks.

Anatomy

  1. IconTone: info (grape) or danger (red).
  2. Title + descriptionaria-labelledby / aria-describedby.
  3. CloseLabelled icon button.
  4. BodyScrolls if long.
  5. FooterSticky, primary last.

Responsive behaviour

  • < 640px: full-width bottom sheet with top corners --radius-xl, slides up.
  • ≥ 640px: centred, scales in.
  • Footer stays visible while the body scrolls.

Theming

Override --dialog-bg and --dialog-radius. Dark dialogs use night-850 (raised above the night-900 cards) with --shadow-4.

Accessibility

Role and pattern

APG Dialog (Modal): role="dialog" aria-modal="true", labelled and described; page behind inert.

Keyboard

KeyAction
Tab / Shift+TabCycles inside the dialog only.
EscCloses (not while busy).
EnterSubmits the form.

Focus

On open: first field, or the safe button for confirmations. On close: back to the trigger.

Labelling

Title in <h2> referenced by aria-labelledby.

Contrast

Text on dialog
Muted on dialog

Motion

Backdrop fades (--duration-base), panel scales/slides (--duration-slow); instant with reduced motion.

Touch

Sheet footer buttons ≥ 44px; the close button is 40px.

Content

  • Titles are questions for confirmations (“Delete Zuri’s Dino Dig 7th?”) and tasks otherwise (“Add a guest”).
  • Say exactly what is lost in destructive dialogs, and what isn’t (bookings stay).
