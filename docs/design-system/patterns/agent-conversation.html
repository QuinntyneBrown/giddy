Talking with Giddy

How the planning agent shows its work, proposes, asks permission and recovers.

WCAG 2.2 AAStatus: stable
  • Overview
  • When to use
  • Structure
  • States
  • Responsive
  • Accessibility
  • Content
  • Do and don't
  • Sources

Overview

Giddy is an agent: it searches venues, compares vendors and drafts plans. The UI keeps parents in control: Giddy shows what it checked, proposes with prices, and never books, pays or messages anyone without an explicit confirmation.

When to use

MomentUI
Parent asksComposer; starter chips on a new chat
Giddy worksTool steps tick off; typing dots; Stop
Giddy proposesPlan card with prices and total vs budget
Parent approvesUse this plan → confirmation dialog listing changes
Giddy nudgesNudges list on Home with one action each
Something failsInline alert in the log; message kept; Send again

States

StateTreatment
emptyGreeting + starter chips
thinkingTool steps + Stop
proposalPlan card
failedAlert in log, Send again / Edit
errorConversation failed to load

Responsive

  • Composer sticks above the bottom nav.
  • Party-at-a-glance aside from 1024px.

Accessibility

  • Log is a polite live region; announce finished messages, not every token.
  • Stop is keyboard reachable (Esc).
  • Agent actions always need explicit confirmation (WCAG 3.3.4).

Content

  • Giddy says what it checked before what it suggests.
  • Giddy uses names and numbers from the plan.
  • Giddy admits uncertainty: “Bubble Bianca usually replies within a day.”
