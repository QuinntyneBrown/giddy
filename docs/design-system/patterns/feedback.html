Pattern

Feedback & loading

Every tap gets a response within 100 ms, and waiting always looks like the thing that’s coming.

WCAG 2.2 AAStatus: stable

Overview

Pick the lightest feedback that does the job: an inline status beside the change, a toast for a completed action, a banner for a lasting condition, a dialog only when a decision is needed.

When to use

Wait / resultUse
< 300 msNothing
Button actionBusy button (aria-busy)
Page loadSkeletons matching the layout
Long job with known sizeDeterminate progress bar
Giddy workingTool steps + typing dots + Stop
Done, reversibleToast with Undo
Failed actionPersistent danger toast or inline alert

States

StateFeedback
LoadingSkeletons
BusySpinner in the pressed button

PartialSection-level alert; rest works
OfflineSticky warning banner; cached content

Responsive

  • Toasts lift above the bottom nav on phones.

Accessibility

  • Live regions for toasts and chat; errors assertive.
  • Skeleton regions aria-busy.
  • Reduced motion stops shimmer.

Content

  • Past tense for results: “Reminder sent to 3 families”.
